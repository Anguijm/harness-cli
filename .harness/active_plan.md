## Goal

Today `harness recall` ranks past failures and learnings by keyword density × recency × `[[link]]` score. That misses semantic matches: a query for "council kept hallucinating accessibility rules" won't surface a section titled "a11y persona invented i18n requirements" even though they're the same topic, because the keyword tokens don't overlap.

Vector retrieval closes that gap. Each chunk in the recall corpus (`learnings.md` sections, `failures.jsonl` entries, council reports) gets a Gemini embedding stored in `.harness/embeddings.json`. At query time, we embed the query and compute cosine similarity against every chunk's embedding, then blend with the existing scorer — vector similarity surfaces semantic matches the keyword scorer would miss; keyword density + recency keep direct hits and recent context dominant.

This is the LLM Wiki / Gbrain pattern: keep the corpus interlinked AND queryable by meaning, not just by literal token overlap.

## Scope (what's in / what's out)

**In:**
- New command `harness reindex` (default: incremental — only embed chunks whose hash changed; `--full` re-embeds everything).
- New library `src/lib/embeddings.js` — load/save index (a JSON file), Gemini REST embedding call, cosine similarity helper, content-hash → embedding cache map.
- `harness recall` blends vector similarity with existing scorer when an index exists; falls back to keyword-only behavior (today's behavior) when no index is present, when the index is stale relative to the corpus, or when `--no-vector` is passed.
- `harness.yml recall.vector_weight` (default 0.5) — relative weight of the vector contribution in the blend; per-repo override.
- `harness.yml recall.auto_reindex` (default false) — if true, recall re-embeds out-of-date chunks lazily before scoring (one-time cost per session); if false, recall warns "index is stale, run `harness reindex`" and proceeds with whatever's in the index.
- Idempotency / sanitization mirroring synthesize and Phase E.1: chunks are content-hash keyed; embeddings persist; chunk content is treated as data and never instructed to the model (embedding endpoint doesn't have a system prompt anyway, but the same sanitizer-strip-control-chars discipline applies before sending text upstream).
- Fail-loud on `--apply` paths (reindex without API key, malformed embedding response, transport error) per the cross-cutting Phase E doctrine.

**Out:**
- No automatic indexing in CI / cron in this PR. Manual invocation (`harness reindex`) and lazy-on-recall (opt-in via `auto_reindex: true`) are both supported.
- No vector clustering / dimensionality reduction / UMAP visualization. Pure cosine similarity is sufficient at the corpus scale these repos hit (≤ a few hundred chunks).
- No re-ranking via cross-encoder. The blend with keyword + recency already produces the dominant ordering signal; cross-encoder is overkill for this corpus.
- No semantic search of source code (the Repository Impact Map's job). Recall is for past failures and learnings only.

## Risk surface

- **Files / modules touched:** `src/commands/recall.js`, `src/commands/reindex.js` (new), `src/lib/embeddings.js` (new), `src/cli.js`, `harness.yml` (+ template), `.gitignore` (+ template), `CLAUDE.md` (+ template), `test/init.test.mjs`. No new package deps — Gemini embedding endpoint via direct `fetch`, same pattern synthesize uses.
- **Cross-system effects:** writes `.harness/embeddings.json` (cache file, gitignored). No mutation of `learnings.md` or `failures.jsonl`. Recall remains read-only.
- **Cost:** embedding calls are cheap (~$0.0001 per 1K input tokens for Gemini text-embedding-004 at the time of writing). A `learnings.md` of ~10K tokens + 50 `failures.jsonl` entries = one-time cost of ~$0.005 to fully index. Incremental reindex (only changed chunks) keeps marginal cost near zero.
- **Rollback plan:** delete `.harness/embeddings.json`; recall falls back to keyword-only. Or pass `--no-vector` to bypass the index without deleting it.

## Implementation decision: where does the blend happen

**Decision: in `recall.js` itself, gated on whether the index file exists and is fresh.** Rationale:
- Single command surface (`harness recall`) for users — they don't need to know whether vectors are available.
- Graceful degradation when no key is set or no index exists: same behavior as today.
- The blend formula is documented in code with the rationale for the default weight, so a future change is auditable.

**Blend formula (default):** `final_score = keyword_score × keyword_weight + cosine_similarity × vector_weight × max_keyword_score`. Multiplying vector contribution by `max_keyword_score` puts it on the same scale as the keyword score so the weights are meaningful at face value (0.5 means "half the influence of a top keyword match"). Without that scaling, raw cosine values (0–1) would always be dominated by the keyword scorer's larger raw values.

## Sanitization discipline

Embedding APIs don't have a system prompt or instruction-following surface, but we apply the same control-character strip and whitespace normalization the synthesizer uses before sending text upstream. Two reasons: (1) consistency with the rest of the harness; (2) some embedding providers do limited content moderation that can be confused by zero-width / bidi-override Unicode in user-supplied text. The shared sanitizer from `synthesize.js` is reused (extract to `src/lib/sanitize.js` if it cleanly factors; otherwise import from synthesize directly).

   - `loadIndex(cwd)` / `saveIndex(cwd, index)` — JSON file at `.harness/embeddings.json`, schema `{ model: string, version: 1, entries: { [contentHash]: { vector: number[], chunkRef: { source, headerOrLineNo } } } }`.
